# 📄 [최종 기획서] 시민 참여형 실시간 종량제 봉투 지도: "봉투어디"

## 1. 프로젝트 개요

- **서비스명:** 봉투모아 (Bongtu-Moa)
- **목적:** 중동 이슈로 인한 종량제 봉투 수급 불안 해소를 위해, 시민들이 직접 판매소별 재고 상태를 공유하는 실시간 지도 서비스.
- **핵심 가치:** **"색상만으로 판단하는 직관성"**과 **"실시간 데이터 신선도"**.

## 2. 기술 스택 (Confirmed Stack)

- **Frontend:** `Next.js 14+` (App Router, Tailwind CSS)
- **Backend/DB:** `Supabase` (PostgreSQL + PostGIS + Realtime)
- **Maps API:** `Kakao Maps API` (국내 주소 및 POI 최적화)
- **Deployment:** `Vercel`

---

## 3. 핵심 기능 상세 (Key Features)

### ① 데이터 소싱 및 동기화

- **기초 데이터:** 공공데이터포털의 '전국종량제봉투판매소표준데이터'를 `Supabase`에 초기 적재.
- **위치 보정:** 주소 데이터를 `Kakao Geocoding API`를 통해 정교한 위·경도 좌표로 변환하여 저장.
- **실시간성:** `Supabase Realtime` 기능을 활용하여, 누군가 제보하는 즉시 접속 중인 모든 사용자의 지도 마커 색상이 즉각 변경됨.

### ② [핵심] 재고 상태별 마커 컬러링 (Marker Logic)

사용자가 지도를 보자마자 상황을 파악할 수 있도록 마커 색상 로직을 엄격히 규정합니다.

| 등급          | 마커 색상            | 판정 기준 (Priority)                            | 사용자 가이드 문구              |
| :------------ | :------------------- | :---------------------------------------------- | :------------------------------ |
| **재고 있음** | **Green** (#22C55E)  | 최근 1시간 이내 "있음" 제보가 우세할 때         | "현재 재고가 확인되었습니다."   |
| **확인 필요** | **Yellow** (#EAB308) | 마지막 제보 후 3시간 경과 혹은 제보가 엇갈릴 때 | "재고가 소진 중일 수 있습니다." |
| **품절**      | **Red** (#EF4444)    | 최근 30분 이내 "없음" 제보가 발생했을 때        | "현재 품절 상태입니다."         |
| **정보 없음** | **Grey** (#94A3B8)   | 6시간 이상 제보가 없거나 데이터가 없는 경우     | "첫 번째 제보를 남겨주세요."    |

### ③ 시민 참여형 제보 시스템 (UX/UI)

- **하단 시트(Bottom Sheet):** 마커 클릭 시 해당 판매소 이름과 함께 [재고 있음 / 품절] 버튼 노출.
- **타임스탬프 표시:** "방금 전 제보됨", "2시간 전 확인됨" 등 정보의 유효 시간을 직관적으로 표시.
- **거리 기반 제보 제한:** (선택 사항) 허위 정보 방지를 위해 사용자의 GPS 위치가 판매소 반경 200m 이내일 때만 제보 활성화.

---

## 4. 시스템 아키텍처 및 데이터 구조

### DB Schema (Supabase)

- **`stores` Table:** `id`, `name`, `address`, `location (geography)`, `current_status (enum)`, `last_reported_at`
- **`reports` Table:** `id`, `store_id (FK)`, `is_available (boolean)`, `created_at`

### API Flow

1.  **Client:** `Kakao Maps`에서 현재 화면 영역(Bounds) 내의 `stores` 좌표 요청.
2.  **Server(Supabase):** PostGIS 기능을 이용해 반경 내 마커 데이터 반환.
3.  **Realtime Subscription:** `reports` 테이블의 변화를 감지하여 `stores`의 `current_status`를 프론트엔드에서 즉시 갱신.

1.  **Step 1:** Supabase 환경 구축 및 공공데이터(CSV) 좌표 변환 후 DB 적재.

4.  **Step 4:** **상태별 마커 색상 변경 로직(Green/Yellow/Red/Grey)** 적용 및 테스트.
5.  **Step 5:** 모바일 최적화(PWA) 및 배포.
